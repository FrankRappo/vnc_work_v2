# cdp/ — текстовый браузер на удалённой машине (0 токенов на зрение)

Дополнение к `rc.sh` (пиксельный драйвер GUI). Решает другой класс задач: **прочитать сайт,
который отдаёт заглушку всему, кроме настоящего браузера**, и получить результат ТЕКСТОМ.

## Зачем

`curl` / `Invoke-WebRequest` к `atol.ru` и `fs.atol.ru` получают ~13.6 КБ JS-антибот-заглушку
(`meta robots noindex` + скрипт, ставящий cookie). Скрипт JS не исполняет → делается ложный
вывод «страницы/файлов нет». Проверено 2026-07-24: заглушка приходит и с RU-IP, и с
браузерным User-Agent — дело не в IP и не в UA.

Настоящий Chrome challenge решает. `cdp/` поднимает на удалённой машине **headless Chrome с
портом отладки** и ходит по страницам через CDP, возвращая DOM/выборку **как текст**:
грепается, не жжёт контекст, не требует GUI-сессии и скриншотов.

Плюс: полученные из браузера cookie (`__js_p_`, `__jhash_`, `__jua_`, …) можно отдать `curl.exe`
на той же машине и качать файлы напрямую (см. «Скачивание»).

## Состав

```
cdp_up.sh         залить cdp_start.ps1 на удалённую машину и поднять браузер (идемпотентно)
cdp_start.ps1     поднять headless Chrome с --remote-debugging-port (изолированный профиль,
                  запуск через schtasks — OpenSSH убивает детей своей сессии)
cdp_get.ps1       Page.navigate + Runtime.evaluate -> текст в файл (на удалённой машине);
                  доверенный клик (Input.dispatchMouseEvent), ожидание предиката, iframe-контекст
cdpq.sh           локальная обёртка: залить скрипт/JS, выполнить по SSH, забрать результат
cdp_net.ps1       запись СЕТИ страницы (Network domain): запросы + тела ответов -> текст в файл
cdpnet.sh         локальная обёртка к cdp_net.ps1
mk_setselect.py   генератор JS: выбрать <option> в ASP.NET-дропдауне и вызвать postback
mk_textsearch.py  генератор JS: вбить фразу в поиск и отправить форму
mk_zipindex.py    генератор JS: прочитать оглавление УДАЛЁННОГО .zip через HTTP Range (без скачивания)
mk_rect.py        генератор JS: координаты вьюпорта для элемента по CSS-селектору (доверенный клик)
js/               готовые выражения: links, form_dump, results_rows, grid_rows, cookies, ua, …
```

## Вождение UI: доверенный клик, ожидание, iframe (T71)

```bash
# ДОВЕРЕННЫЙ клик по координатам вьюпорта (не синтетический el.click())
CDP_NONAV=1 CDP_CLICK="1038,231" bash cdpq.sh - /tmp/o.txt 4000 js/pagetext.js
CDP_CLICKS=2 …            # двойной клик (две пары press/release: 1, затем 2)
CDP_BTN=right …           # правая кнопка (контекстное меню)

# ЖДАТЬ появления, а не гадать паузой: предикат опрашивается до истины, печатает WAIT=OK|TIMEOUT
CDP_NONAV=1 CDP_WAIT='document.querySelectorAll("iframe").length>0' CDP_WAITMS=25000 \
  bash cdpq.sh - /tmp/o.txt 1000 js/pagetext.js

# выполнить выражение ВНУТРИ iframe (его СОБСТВЕННЫЙ main world -> видны переменные страницы)
CDP_NONAV=1 CDP_FRAME="fd_00085414" bash cdpq.sh - /tmp/o.txt 1500 ./my_frame_expr.js
```

## Сеть страницы: брать данные из ответа сервера, а не из DOM

```bash
CDP_CLICK="76,123" bash cdpnet.sh /tmp/net.txt 12            # клик -> что он дёрнул (с телами)
bash cdpnet.sh /tmp/net.txt 15 uidl                          # только URL с подстрокой uidl
CDP_NAV="https://lk.example/x" CDP_MAXBODY=400000 bash cdpnet.sh /tmp/net.txt 20 api
CDP_NOBODY=1 bash cdpnet.sh /tmp/index.txt 20                # индекс запросов без тел
```

Зачем: в кабинетах (Vaadin/SPA) значения в DOM уже отформатированы и разложены по свёрнутым
блокам, а в JSON-ответе они лежат сырыми. Плюс видно, ЧТО сервер ответил на клик: пустой UIDL
(`for(;;);[{"syncId":..}]` без `execute`) — доказательство, что «кнопка нажалась, но делать
нечего», а не что клик не дошёл.

## Быстрый старт

```bash
# 1) поднять браузер на удалённой машине (идемпотентно: зальёт скрипт и запустит)
bash cdp_up.sh

# 2) страница -> текст (весь DOM)
bash cdpq.sh https://fs.atol.ru/ /tmp/page.html 10000

# 3) страница -> только ссылки
bash cdpq.sh https://fs.atol.ru/ /tmp/links.txt 9000 js/links.js

# 4) действие на УЖЕ открытой странице (клик/postback), без навигации
CDP_NONAV=1 bash cdpq.sh - /tmp/out.txt 5000 js/click_search.js
```

Канал параметризован: `SSH=`, `SCP=`, `RHOST=`, `RDIR=`, `CDP_PORT=` — тот же инструмент
работает против любой машины, у которой есть пара хелперов ssh/scp.

## Скачивание файлов из-за антибота

```bash
bash cdpq.sh https://fs.atol.ru/ /tmp/ck.txt 9000 js/cookies.js   # cookie из браузера
CDP_NONAV=1 bash cdpq.sh - /tmp/ua.txt 2500 js/ua.js              # его же User-Agent
# -> положить оба на удалённую машину и качать: curl.exe -A <ua> -H "Cookie: <ck>" <url>
```

🔴 Cookie живут недолго (у fs.atol.ru — минуты). Если скачался файл ровно **13602 байта** —
это заглушка: обнови cookie и повтори. UA обязан совпадать с тем, чьи cookie взяты
(`__jua_` привязан к UA); у headless-Chrome в UA стоит `HeadlessChrome/...`.

## Гочи (стоили отладочных кругов)

1. **`ClientWebSocket` допускает ТОЛЬКО ОДИН незавершённый `ReceiveAsync`.** Цикл «выдать
   receive → по таймауту бросить → выдать новый» роняет сокет: `.Wait()` кидает
   `AggregateException`. В `cdp_get.ps1` незавершённая задача хранится в `$script:pending` и
   **возобновляется**, а не выдаётся заново.
2. **`__doPostBack` / `.click()` надо откладывать через `setTimeout`.** Перезагрузка страницы
   сносит JS-контекст, и `Runtime.evaluate` не успевает вернуть значение → `EVAL=NULL`, и
   отлаживаешь не то. Генераторы `mk_*.py` ставят задержку 200–300 мс сами.
3. **Кириллицу в JS — только `\uXXXX`-экранированием.** Файл выражения проходит scp и
   `[IO.File]::ReadAllText`; ASCII-исходник исключает класс ошибок кодировки.
4. **С `-NoNav` аргумент `-Url` НЕ передавать вообще.** `-Url "-"` биндер PowerShell принимает
   за посторонний позиционный аргумент, и вся команда молча привязывается не туда.
5. **`--dump-dom` на этой машине не работает** (Chrome не завершается, stdout пуст). Порт
   отладки + CDP — рабочий путь; заодно даёт cookie, POST-и и повторные действия.
6. **Профиль — только свой.** `--user-data-dir` всегда указывает на отдельный каталог: чужой
   работающий Chrome держит эксклюзивную блокировку на `Default\Network\Cookies` (её не берут
   ни `Copy-Item`, ни `FileShare::ReadWrite`, ни `esentutl /y`), и лезть в него незачем.
7. **`schtasks` предупреждает про `/ST` в прошлом** — это не ошибка, задача всё равно
   запускается через `schtasks /run`.
8. **Компонентные гриды не верят синтетическому клику.** `el.click()` хватает обычной кнопке
   (и вкладке Vaadin), но строка `vaadin-grid` на него не реагирует: контент ячеек лежит в
   СВЕТЛОМ DOM (`vaadin-grid-cell-content`), а `<td>` в shadow DOM держит только `<slot>`.
   Рабочий путь — `CDP_CLICK="x,y"` (`Input.dispatchMouseEvent`), координаты брать у
   `getBoundingClientRect()` нужной ячейки.
9. **Двойной клик = ДВЕ пары press/release с `clickCount` 1, затем 2.** Одно событие с
   `clickCount:2` `dblclick` в Chrome НЕ порождает. Карточка, открывающаяся по двойному клику
   (так устроен ЛК ОФД-Я), при этом молчит — и вывод «клик не доходит» будет ложным.
10. **Модалка может быть `<iframe>` — и `innerText` страницы её НЕ покажет.** Признак «ничего
    не открылось» по тексту страницы недостоверен: проверяй `document.querySelectorAll('iframe')`
    (или дампи `outerHTML` и грепай). Содержимое читать `-Frame <подстрока URL>` (main world
    фрейма, видны его JS-переменные) либо `fetch(src)` из top-фрейма, если тот же origin.
11. **Фиксированный `-SettleMs` — ставка.** Проиграв её, читаешь страницу ДО прихода данных.
    `CDP_WAIT='<предикат>'` опрашивает до истины и печатает `WAIT=OK|TIMEOUT`, так что промах
    виден, а не превращается в неверный вывод.

12. **`/api/v3/facade/*` у кабинетов ЦРПТ — вечный `403 nginx`** (и из PowerShell, и из same-origin
    fetch настоящего браузера, с токеном и куками). Это мёртвый префикс из старого бандла, а не
    «нас не пускают»: живой API — `/bff-elk/...`, и он принимает `Authorization: Bearer` из любого
    клиента. Роль браузера — только УЗНАТЬ имена ручек через `cdpnet.sh`.
13. **Грепать бандл SPA выгодно раньше, чем водить UI.** `localStorage.setItem("<ключ>"` даёт способ
    аутентификации, литералы путей — список ручек. Но осторожно: в бандле лежат и МЁРТВЫЕ пути
    (см. гочу 12), поэтому найденное надо подтверждать записью сети живой страницы.

## Секреты в выражении: `CDP_REMOTE_JS` (T72)

```bash
# выражение уже ЛЕЖИТ на удалённой машине -- не заливается и не удаляется
CDP_NONAV=1 CDP_REMOTE_JS='C:\Users\User\setauth.js' bash cdpq.sh - /tmp/o.txt 1500
CDP_REMOTE_JS='C:\Users\User\call_api.js' bash cdpnet.sh /tmp/net.txt 20 bff
```
Нужно, когда в выражении обязан быть секрет (auth-токен, код маркировки): файл генерируется НА машине
(`rps.sh`, читая токен из файла), а сюда передаётся только его имя. Секрет не проходит через контекст
оркестратора и не остаётся в локальных артефактах.

## Координаты для доверенного клика: `mk_rect.py` (T72)

```bash
python3 mk_rect.py 'a[href*="water.crpt.ru"]' --scroll > js/r_water.js
CDP_NONAV=1 bash cdpq.sh - /tmp/r.txt 1500 js/r_water.js     # -> "#1 657,657 w=407 h=272 vis=true ..."
CDP_CLICK="657,657" bash cdpnet.sh /tmp/net.txt 20           # -> клик по этим координатам
```
`--text 'Найти'` фильтрует по видимому тексту, `--nth N` — только N-е совпадение.
🔴 `--scroll` обязателен для элемента ниже сгиба: `Input.dispatchMouseEvent` берёт координаты ВЬЮПОРТА,
и элемент на `y=2049` при высоте вьюпорта 1105 не кликается вообще (признак — `vis=false`).
