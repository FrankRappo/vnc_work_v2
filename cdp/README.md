# cdp/ — текстовый браузер на удалённой машине (0 токенов на зрение)

Дополнение к `rc.sh` (пиксельный драйвер GUI). Решает другой класс задач: **прочитать сайт,
который отдаёт заглушку всему, кроме настоящего браузера**, и получить результат ТЕКСТОМ.

## Зачем

`curl` / `Invoke-WebRequest` к `atol.ru` и `fs.atol.ru` получают ~13.6 КБ JS-антибот-заглушку
(`meta robots noindex` + скрипт, ставящий cookie). Скрипт JS не исполняет → делается ложный
вывод «страницы/файлов нет». Проверено 2026-07-24: заглушка приходит и с RU-IP, и с
браузерным User-Agent — дело не в IP и не в UA.

Настоящий Chrome challenge решает. `cdp/` поднимает на удалённой машине **headless Chrome с
портом отладки** и ходит по страницам через CDP, возвращая DOM/выборку **как текст**:
грепается, не жжёт контекст, не требует GUI-сессии и скриншотов.

Плюс: полученные из браузера cookie (`__js_p_`, `__jhash_`, `__jua_`, …) можно отдать `curl.exe`
на той же машине и качать файлы напрямую (см. «Скачивание»).

## Состав

```
cdp_start.ps1     поднять headless Chrome с --remote-debugging-port (изолированный профиль,
                  запуск через schtasks — OpenSSH убивает детей своей сессии)
cdp_get.ps1       Page.navigate + Runtime.evaluate -> текст в файл (на удалённой машине)
cdpq.sh           локальная обёртка: залить скрипт/JS, выполнить по SSH, забрать результат
mk_setselect.py   генератор JS: выбрать <option> в ASP.NET-дропдауне и вызвать postback
mk_textsearch.py  генератор JS: вбить фразу в поиск и отправить форму
mk_zipindex.py    генератор JS: прочитать оглавление УДАЛЁННОГО .zip через HTTP Range (без скачивания)
js/               готовые выражения: links, form_dump, results_rows, reset, cookies, ua, …
```

## Быстрый старт

```bash
# 1) поднять браузер на удалённой машине (идемпотентно)
bash /work/vnc_work/ofd_ssh.sh 'powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\User\cdp_start.ps1'

# 2) страница -> текст (весь DOM)
bash cdpq.sh https://fs.atol.ru/ /tmp/page.html 10000

# 3) страница -> только ссылки
bash cdpq.sh https://fs.atol.ru/ /tmp/links.txt 9000 js/links.js

# 4) действие на УЖЕ открытой странице (клик/postback), без навигации
CDP_NONAV=1 bash cdpq.sh - /tmp/out.txt 5000 js/click_search.js
```

Канал параметризован: `SSH=`, `SCP=`, `RHOST=`, `RDIR=`, `CDP_PORT=` — тот же инструмент
работает против любой машины, у которой есть пара хелперов ssh/scp.

## Скачивание файлов из-за антибота

```bash
bash cdpq.sh https://fs.atol.ru/ /tmp/ck.txt 9000 js/cookies.js   # cookie из браузера
CDP_NONAV=1 bash cdpq.sh - /tmp/ua.txt 2500 js/ua.js              # его же User-Agent
# -> положить оба на удалённую машину и качать: curl.exe -A <ua> -H "Cookie: <ck>" <url>
```

🔴 Cookie живут недолго (у fs.atol.ru — минуты). Если скачался файл ровно **13602 байта** —
это заглушка: обнови cookie и повтори. UA обязан совпадать с тем, чьи cookie взяты
(`__jua_` привязан к UA); у headless-Chrome в UA стоит `HeadlessChrome/...`.

## Гочи (стоили отладочных кругов)

1. **`ClientWebSocket` допускает ТОЛЬКО ОДИН незавершённый `ReceiveAsync`.** Цикл «выдать
   receive → по таймауту бросить → выдать новый» роняет сокет: `.Wait()` кидает
   `AggregateException`. В `cdp_get.ps1` незавершённая задача хранится в `$script:pending` и
   **возобновляется**, а не выдаётся заново.
2. **`__doPostBack` / `.click()` надо откладывать через `setTimeout`.** Перезагрузка страницы
   сносит JS-контекст, и `Runtime.evaluate` не успевает вернуть значение → `EVAL=NULL`, и
   отлаживаешь не то. Генераторы `mk_*.py` ставят задержку 200–300 мс сами.
3. **Кириллицу в JS — только `\uXXXX`-экранированием.** Файл выражения проходит scp и
   `[IO.File]::ReadAllText`; ASCII-исходник исключает класс ошибок кодировки.
4. **С `-NoNav` аргумент `-Url` НЕ передавать вообще.** `-Url "-"` биндер PowerShell принимает
   за посторонний позиционный аргумент, и вся команда молча привязывается не туда.
5. **`--dump-dom` на этой машине не работает** (Chrome не завершается, stdout пуст). Порт
   отладки + CDP — рабочий путь; заодно даёт cookie, POST-и и повторные действия.
6. **Профиль — только свой.** `--user-data-dir` всегда указывает на отдельный каталог: чужой
   работающий Chrome держит эксклюзивную блокировку на `Default\Network\Cookies` (её не берут
   ни `Copy-Item`, ни `FileShare::ReadWrite`, ни `esentutl /y`), и лезть в него незачем.
7. **`schtasks` предупреждает про `/ST` в прошлом** — это не ошибка, задача всё равно
   запускается через `schtasks /run`.
